# Independent Fork development prerelease scope

**Candidate:** `tiic-tech/archify` `v3.3.0-dev.1`, a development prerelease of the integrated Archify product, not an official `tt-a1i/archify` stable release. This document describes intended scope, not a claim that a tag, release, installation or deployment exists. Apache-2.0 licensing and existing attribution remain in force.

## Foundation included

The existing native-diagram and Explainer capabilities are retained. The workspace foundation supports source-backed research drafts, typed facts and scoped questions, native Feature workflows, opt-in structured PRD composition, readiness diagnostics, separately approved client projections, versioned source and supported incremental packets. Packaged generic starter and authoring resources explain the current path. The offline reader and its explicit feedback exchange are non-authoritative projections; validation, review hashes and a Git revision do not constitute business confirmation.

The author/Agent interprets source material. Automatic arbitrary-document interpretation, durable direct canvas authoring and autosave, cloud collaboration, and a business-approval process are not delivered by this foundation. The continuing product goal is one evolving workspace, not a detached PRD exporter. See [product goal](PRODUCT_GOAL.md) and [backward plan](BACKWARD_PLAN.md).

## Separate gates and deferred channels

Independent review, final integration-source and archive verification, remote CI and compatibility gates, generic forward-use/content/iteration evidence, and any actual release remain required. A local archive build is not release acceptance. Installation, local deployment, rollback and user guide require their own authorized, verified actions.

This Fork development prerelease does **not** advance the official stable notifier or its trusted upstream URL. Main/Pages deployment, official stable publication, npm/DSH plugin publication or pin changes, Hermes distribution changes, and updates to existing user installations are out of scope and deferred to separately reviewed decisions. A development package identity does not assert that any of those channels has been published or updated.
